moai 사용 방법

설치

설치 스크립트는 릴리스 파일과 SHA256SUMS를 함께 내려받고, 체크섬이 맞지 않으면 설치하지 않습니다. 이 검사를 끄는 옵션은 없습니다.

macOS · Linux

curl -fsSL https://raw.githubusercontent.com/buzzni/moai/main/install.sh | sh
  • 기본 설치 위치는 ~/.local/bin 입니다. 이 디렉터리가 PATH에 있어야 moai로 부를 수 있습니다.
  • 다른 위치나 특정 버전으로 설치하려면 -s -- 뒤에 옵션을 붙입니다. 
    curl -fsSL https://raw.githubusercontent.com/buzzni/moai/main/install.sh \
  | sh -s -- --dir ~/bin --version v0.1.0

Windows

PowerShell에서 스크립트를 내려받아 파일로 실행합니다.

Invoke-WebRequest -UseBasicParsing -OutFile install.ps1 https://raw.githubusercontent.com/buzzni/moai/main/install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
  • 기본 설치 위치는 %LOCALAPPDATA%\Programs\moai 입니다. -Dir로 위치를, -Version으로 버전을 고를 수 있습니다.
  • 설치 스크립트는 PATH를 고치지 않습니다. 설치 위치가 PATH에 없으면 한 줄로 알려 줍니다.
  • irm … | iex 처럼 파이프로 실행하는 방식은 지원하지 않습니다. 스크립트가 끝날 때 PowerShell 창이 함께 닫히기 때문입니다.
  • Visual C++ 재배포 패키지가 없는 깨끗한 PC 에서도 그대로 실행됩니다.

업데이트

moai update

지금 실행 중인 moai를 최신 릴리스로 바꿉니다. 새 버전이 나오면 moai tui 화면 위쪽에도 표시됩니다. 처음 설치할 때 쓴 설치 명령을 다시 실행해도 업데이트됩니다.

지원하는 플랫폼

미리 빌드한 바이너리는 Linux(x86_64), macOS(Apple Silicon), Windows(x86_64·ARM64) 용이 있습니다. 그 밖의 환경에서는 소스에서 cargo build --release로 빌드합니다.

시작하기

moai로 관리할 프로젝트의 루트에서 한 번 실행합니다.

cd <프로젝트>
moai init

터미널에서 실행하면 설정 화면이 먼저 나옵니다. 각 항목에는 기본값이 선택되어 있습니다. Enter를 누르면 선택한 설정으로 초기화하고, Esc를 누르면 변경 없이 종료합니다.

moai init
선택 항목무엇을 정하나고르는 법
id 접두어이슈 id의 앞부분입니다(moai-ae8y의 moai). 기본값은 디렉터리 이름입니다나중에 바꿀 수 없으니 짧고 알아보기 쉬운 이름으로 정합니다
트래커를 git에 올릴지commit: 저장소에 커밋해 동료와 공유합니다(기본값)
exclude: 내 클론에만 두고 .git/info/exclude로 숨깁니다
gitignore: 내 클론에만 두고 .gitignore로 숨깁니다		팀과 함께 쓰면 commit, 남의 저장소에서 내 할 일만 관리하려면 exclude
에이전트 안내문 위치block: AGENTS.md 안에 안내문 전체를 넣습니다
file: 안내문은 .moai/guide.md에 두고 AGENTS.md에는 링크만 남깁니다
hook: AGENTS.md는 건드리지 않고 훅이 Claude 에 알려 줍니다
none: 아무것도 쓰지 않습니다		AGENTS.md를 짧게 두고 싶으면 file. 트래커를 git에 올리지 않으면 hook
훅과 스킬 설치Claude Code 플러그인(스킬과 훅)을 설치합니다에이전트와 함께 쓴다면 켭니다. 아래 훅에 대한 설명 참고
└ 선택 스킬moai-tmux · moai-cmux · moai-saycode가 한 줄씩 나옵니다쓰는 작업 환경에 맞춰 켭니다. 지금 tmux·cmux·Saycode 안에서 실행 중이면 해당 줄이 미리 켜져 있습니다
머지 드라이버브랜치 둘이 서로 다른 이슈를 고쳤을 때 git이 이슈 단위로 알아서 합치게 합니다트래커를 git에 올리면 켭니다(클론마다 한 번 필요합니다)
프로젝트 목록에 추가내 프로젝트 목록에 이 저장소를 등록합니다여러 프로젝트를 쓰면 켭니다. 프로젝트 밖에서 moai를 실행하면 등록한 프로젝트를 한 화면에 모아 보여 줍니다
  • Claude Code는 AGENTS.md가 아니라 CLAUDE.md를 읽습니다. CLAUDE.md에 @AGENTS.md 한 줄을 넣어 두면 둘 다 읽습니다.
  • Codex · Antigravity에서도 쓰려면 moai skill install --agent codex, --agent antigravity로 각자의 스킬과 훅을 설치합니다.
  • moai를 업데이트한 뒤에는 moai init을 다시 실행해 안내문을 새 버전으로 바꿉니다. 이슈와 이력은 건드리지 않습니다.

설치가 끝나면 에이전트 세션을 열고 평소처럼 말로 일을 시키면 됩니다. 에이전트가 세션을 시작할 때 moai status로 현재 보드를 읽고, 이슈를 만들고 옮기는 일을 알아서 합니다.

tui 와 web

moai의 화면은 두 가지입니다. 에이전트는 화면을 열지 않아도 트래커 파일을 직접 읽고 수정합니다. 사용자는 진행 상황을 확인할 때 원하는 화면을 열면 됩니다.

moai tui — 터미널에서

moai tui

목록, 칸반, 간트, 통계, 위키를 터미널에서 봅니다. SPC g를 누른 뒤 화면별 키 하나를 누르면 전환됩니다. 다시 실행하면 마지막으로 보던 목록, 칸반, 간트 화면이 열립니다.

moai tui
  • 마우스로 행을 클릭하거나 스크롤하고, 창 너비를 조절할 수 있습니다. 전체 키 목록은 moai tui --help에서 확인합니다.
  • SPC n을 누르면 떠오른 생각을 바로 백로그에 적을 수 있습니다.

moai web — 브라우저에서

moai web

127.0.0.1:6624에서 목록, 칸반, 간트, 위키를 봅니다. 브라우저는 직접 열어야 합니다. 터미널이 익숙하지 않은 동료와 진행 상황을 공유할 때 쓸 수 있습니다.

  • 키는 tui와 거의 같습니다. 창 사이를 옮길 때만 Ctrl-w 대신 SPC w를 씁니다. 통계는 tui에서만 볼 수 있습니다.
  • 간트 막대를 끌어 날짜를 바꿀 수 있습니다. 그 밖의 트래커 내용은 읽기만 합니다.
  • 포트가 이미 사용 중이면 --port로 다른 포트를 지정합니다. --port 0을 주면 빈 포트를 고릅니다.
  • 종료하려면 Ctrl-C를 누릅니다.

목록 — 마일스톤과 에픽을 폴더처럼

마일스톤과 에픽을 펼치거나 그 안으로 들어가 이슈를 찾습니다. 커서가 놓인 이슈의 설명, 하위 이슈, 커밋, 이력은 옆에 표시됩니다. tui와 web 모두 SPC g l로 엽니다.

moai tui
127.0.0.1:6624
  • Enter로 마일스톤이나 에픽에 들어가고, Backspace로 나옵니다. l은 한 단계 펼치고, h는 접습니다. Tab은 하위 항목을 모두 펼칩니다.
  • /를 누르고 검색어를 입력하면 제목, 태그, 본문, 노트에서 바로 찾습니다. 숨긴 이슈도 검색됩니다. 보관한 이슈는 web에서는 SPC v o로 보관함을 켰을 때만 검색됩니다.
  • SPC f로 상태, 담당자, 태그, 마일스톤 등의 조건을 걸 수 있습니다. 입력하는 동안 선택할 수 있는 값이 위에 표시됩니다.
  • SPC s로 우선순위, 기한, 갱신 시각 등 여러 기준을 조합해 정렬합니다. 정렬 설정은 다음에 실행할 때도 유지됩니다.
  • 내게 배정된 이슈에 변경이 생기면 [NEW]가 붙습니다. r로 읽음 처리합니다.

칸반 — 상태별 보드

이슈를 상태별로 나눠 카드로 보여 줍니다. 마일스톤마다 한 줄씩 배치되어 릴리스별 진행 상황을 볼 수 있습니다. tui와 web 모두 SPC g b로 엽니다.

moai tui
127.0.0.1:6624
  • 백로그와 미뤄 둔 일도 별도 칸에 표시됩니다. 미뤄 둔 칸은 기본으로 숨겨져 있으며, SPC v l로 표시합니다.
  • tui에서는 다른 사람의 카드에 담당자가 표시됩니다. web에서는 SPC c a로 담당자를 켭니다.
  • h, l로 칸을 옮기고, j, k로 칸 안의 카드를 오갑니다.
  • 목록과 커서 위치, 필터, 보기 설정을 공유합니다. 두 화면을 오가도 보던 위치가 유지됩니다.
  • 카드를 직접 옮길 수는 없습니다. 상태는 에이전트가 작업하면서 바꿉니다.

간트 — 일정을 막대로

목록 옆에 날짜 축을 붙여, 이슈마다 계획한 기간과 실제로 일한 기간을 막대로 봅니다. tui와 web 모두 SPC g g로 엽니다.

moai tui
127.0.0.1:6624
  • 흐린 막대는 계획한 시작일부터 기한까지, 색 막대는 실제로 일한 기간입니다. 기한을 넘긴 부분은 빨간 빗금으로 보입니다.
  • 에픽과 마일스톤은 멤버들의 기간을 모아 빗금 막대로 보여 줍니다.
  • 시간, 일, 주, 월 단위로 넓히고 좁힐 수 있습니다. t는 오늘로 돌아가고, z는 모든 막대를 한 화면에 맞춥니다.
  • 커서가 놓인 이슈를 막고 있는 이슈는 화살표로 이어집니다.
  • 막대를 마우스로 끌면 시작일과 기한이 바뀝니다. 손을 놓을 때 한 번 저장되고, 위의 에픽이나 마일스톤 기한을 넘기면 저장하지 않고 이유를 알려 줍니다.

통계 — 흐름과 걸린 시간

프로젝트의 작업 현황을 막대그래프와 수치로 봅니다. tui에서 SPC g s로 엽니다. web에는 없습니다.

moai tui
  • 주별로 만든 일과 끝낸 일을 나란히 보여 줍니다. b로 주 단위와 일 단위를 바꿉니다.
  • 상태별, 우선순위별 이슈 수를 확인할 수 있습니다.
  • 생성부터 완료까지, 작업 시작부터 완료까지 걸린 시간의 중앙값과 p90을 보여 줍니다. 시작 시각을 모르는 일은 0으로 계산하지 않고 별도로 셉니다.
  • 이슈에 기록된 모델 이름을 기준으로 AI 모델별 작업 수를 집계합니다.
  • 필터가 설정되어 있으면 조건에 맞는 이슈만 집계합니다.

위키 — 저장소의 매뉴얼

저장소의 마크다운 문서를 화면 안에서 읽습니다. tui와 web 모두 SPC g w로 엽니다.

moai tui
127.0.0.1:6624
  • 한쪽에는 페이지 목록이, 다른 쪽에는 선택한 페이지의 내용이 나옵니다.
  • /로 제목과 본문을 검색합니다. 검색어와 잘 맞는 페이지부터 표시됩니다.
  • 페이지 안의 링크는 Tab으로 골라 Enter로 엽니다. Backspace를 누르면 이전에 읽던 줄로 돌아갑니다.
  • 이슈 상세에서는 커밋 아래에 해당 이슈를 다루는 위키 페이지와 관련 절도 표시됩니다.
  • 위키는 읽기 전용입니다. 페이지는 저장소 파일로 관리하며, 에이전트가 작업을 마칠 때 수정하고 커밋합니다.

moai로 시작하는 개발 지시

큰 작업은 마일스톤과 에픽으로 나눕니다

moai에서는 에픽과 마일스톤으로 이슈를 묶어 관리합니다.

  • 에픽 — 한 가지 목적을 위한 이슈 묶음입니다. 여러 파일을 수정해야 하는 요청이라면 에이전트가 에픽 하나와 이슈 3~7개로 나눈 계획을 먼저 보여 주고, 승인하면 한 번에 만듭니다.
  • 마일스톤 — 한 번에 내보낼 릴리스 단위입니다. 에픽을 마일스톤에 연결하면 하위 이슈도 함께 포함됩니다.

에픽과 마일스톤의 상태는 직접 옮기지 않습니다. 하위 작업을 하나라도 시작하면 진행 중으로, 모두 끝내면 완료로 자동 변경됩니다.

마일스톤이 진행 중일 때는 그 안의 일이 먼저입니다. moai ready는 진행 중인 마일스톤의 일과 p0(긴급) 만 내주고, 나머지는 뒤로 미룹니다. 진행 중인 마일스톤에 작업을 추가할지는 사용자가 결정합니다.

계획을 보여 줄 때 에이전트는 마감일도 함께 묻습니다. 답하지 않으면 마감일 없이 둡니다.

워크트리를 만들고 머지하는 과정

여러 세션이 한 브랜치에 커밋을 쌓으면 머지할 때 서로를 기다리게 됩니다. moai의 에이전트는 작업마다 별도의 브랜치를 만듭니다.

  1. 작업을 맡습니다. 이슈를 in_progress로 옮깁니다(moai mv <id> in_progress --from todo). 다른 세션이 이미 맡았다면 옮기지 않고 다음 일로 넘어갑니다.
  2. 워크트리를 만듭니다. 저장소 안의 .worktrees/<에픽>에 새 브랜치로 체크아웃합니다. Claude Code · Codex · Antigravity가 모두 같은 자리를 씁니다.
  3. 그 안에서 작업하고 커밋합니다. 커밋 제목에 이슈 id를 적어 두면 moai show <id>가 그 이슈의 커밋을 찾아 보여 줍니다.
  4. 리뷰를 받습니다. 에픽이 끝나면 에픽 전체를 한 번 리뷰하고, 리뷰 의견을 반영합니다.
  5. 머지하고 정리합니다. 기본 브랜치로 --no-ff 머지하고, 워크트리와 브랜치를 지운 뒤 이슈를 done으로 옮깁니다.
  • 트래커는 늘 루트에 있습니다. 워크트리 안에서 moai를 실행해도 루트의 .moai/를 읽고 씁니다. 다른 세션에서도 작업 배정 상태를 바로 확인할 수 있고, 머지할 때 트래커 파일이 충돌하지 않습니다.
  • 마일스톤에 속한 작업은 마일스톤 브랜치에서 시작합니다. milestone/<마일스톤 id> 브랜치에서 에픽 브랜치를 만들고, 작업이 끝나면 다시 마일스톤 브랜치로 머지합니다. 마일스톤 브랜치는 릴리스할 때 한 번에 기본 브랜치로 들어갑니다.
  • 옆 워크트리가 무엇을 하고 있는지는 moai ready --worktree로 봅니다.

  • 백로그는 아직 실행할 작업으로 확정되지 않은 아이디어입니다. 보드와 moai ready에는 표시되지 않습니다.
  • 작업 중 떠오른 아이디어가 현재 범위를 벗어난다면 백로그에 남겨 둡니다.
  • 때가 되면 moai backlog promote <id>로 에픽과 이슈를 만듭니다. 원래 백로그는 닫히고, 새 작업의 이력에서 기존 메모를 확인할 수 있습니다.
  • 이미 만든 일을 지금은 안 하기로 했다면 백로그가 아니라 moai defer <id> -m '이유'로 미룹니다. --undo로 그대로 되돌릴 수 있습니다.

사용 예

에이전트에게는 말로 지시합니다. 다음과 같이 요청할 수 있습니다.

백로그 정리

쌓인 백로그를 정리해 줘. 겹치는 건 합치고, 이미 끝난 건 닫고, 지금 할 만한 건 우선순위를 매겨 줘.

쌓인 백로그를 쉬고 있는 세션에 나눠 줘.

두 번째 문구는 감독(/moai-supervise)을 부릅니다. 아래 감독과 일꾼 사용 참고.

계획은 Fable 로, 자세하게

작업에 대한 계획을 claude fable 로 하고, 설명을 상세하게 작성해서 다른 에이전트가 바로 참고할 수 있게 해 줘.

계획 단계에서 이슈 본문에 무엇을 왜 하는지, 어디까지 진행할지, 어떤 파일을 수정할지 정리해 두면 다른 에이전트도 맥락을 파악하고 작업을 이어갈 수 있습니다.

개발과 리뷰에 다른 모델 쓰기

각 일꾼 세션에서 서브에이전트를 활용하여 sonnet 5.5 medium 으로 개발하고, opus 5.5 high 로 리뷰해 줘.

이 설정을 매번 말하지 않으려면 역할별 모델을 사용자 설정에 적어 둡니다. 감독은 일을 나눌 때마다 이 값을 읽습니다. moai models로 지금 값을 확인합니다.

[models]
plan    = "fable"    # 계획
develop = "sonnet"   # 개발 — 대부분의 일
complex = "opus"     # 쓰기 경로·동시성·여러 파일에 걸친 일
review  = "opus"     # 에픽 끝 리뷰
review_grade = "high"
effort       = "medium"

지원하는 작업 환경

감독이 일꾼 창을 확인하고 조작할 수 있는 환경에서는 세션 관리까지 맡길 수 있습니다. 쓰는 환경에 맞는 선택 스킬을 켭니다(moai init의 선택 스킬 줄, 또는 moai skill install --with <스킬>).

  • tmux — moai-tmux. 감독이 일꾼 칸에 라벨을 달고, 보고가 끝난 칸을 /clear로 비우고, 전달되지 않은 메시지를 붙여 넣습니다. 일꾼이 모자라면 허락을 받고 새 칸을 엽니다.
  • cmux — moai-cmux(cmux 0.65.0 이상). tmux와 같은 일을 cmux 탭에서 합니다.
  • Saycode — moai-saycode. Saycode 세션 안에서 감독이 happy agent로 일꾼 세션을 보고, 일을 보내고, 새 세션을 엽니다.

어느 환경에서도 감독은 사용자의 칸·탭·세션을 닫지 않고, 입력창에 사람이 쓰던 글이 있으면 건드리지 않습니다.

훅에 대한 설명

moai skill install(또는 moai init의 훅·스킬 설치)을 하면 에이전트 세션의 주요 시점에 moai 훅이 실행됩니다.

언제무엇을 하나
세션 시작경고의 기준점을 적어 둡니다. 맥락이 압축된 뒤에는 진행하던 작업을 다시 알려 줍니다
첫 프롬프트moai status 보드를 한 번 읽혀 줍니다
도구 실행 전아래 다섯 규칙을 확인합니다
턴 종료진행 중인 작업이 남아 있으면 다음 세션을 위한 Next: 메모를 남기도록 안내합니다

훅이 지키는 다섯 규칙:

  1. 새 이슈는 현재 맡은 작업 범위 안에서 만듭니다. 범위 밖이면 백로그로 보냅니다.
  2. 저장소를 수정하기 전에 작업을 맡습니다.
  3. 리뷰도 이슈로 남깁니다. 무엇을 보는지, 무엇을 반영했는지 적습니다.
  4. 사용자의 tmux 서버를 죽이지 않습니다.
  5. 다른 에이전트의 작업을 맡으려면 먼저 확인합니다.

거절할 때는 통과하는 명령을 그대로 알려 주므로 에이전트가 사람을 기다리지 않고 바로 고칩니다(5번만 사람에게 묻습니다). 훅은 세션을 실패시키지 않고, 터미널에서 사람이 직접 치는 moai는 훅을 지나지 않습니다.

감독과 일꾼 사용

Claude Code 세션 하나에서 /moai-supervise를 부르면 그 세션이 감독이 됩니다. 감독은 저장소마다 하나만 둡니다.

tmux · moai tui · Claude Code · Codex · Antigravity
  1. 감독이 서로 겹치지 않는 백로그를 고릅니다. 마감일이 없으면 묻습니다.
  2. 일의 난이도에 맞는 역할(개발·복잡한 일·문서·잔일)을 고르고, 그 역할의 모델로 일꾼을 띄웁니다. 기본은 감독 세션 안의 서브에이전트입니다.
  3. 일꾼은 백로그를 에픽으로 구체화하고, 워크트리에서 작업하고, 리뷰·머지·정리까지 마친 뒤 보고합니다.
  4. 감독은 머지가 됐는지, 에픽이 닫혔는지, 워크트리가 지워졌는지 확인하고 다음 일을 보냅니다.
  • 일꾼 창을 직접 보고 싶으면 서브에이전트 대신 세션 일꾼을 씁니다. 저장소 루트에서 Claude Code 세션을 몇 개 열어 두면, 감독이 쉬고 있는 세션에 일을 보냅니다.
  • 설계 결정이 필요하면 일꾼이 멈추고 감독이 사람에게 묻습니다. 자리를 비울 때는 감독에게 알려 두면 일꾼이 권장안으로 정하고 이유를 이슈에 남깁니다.
  • 감독은 작업 선정과 배정, 결과 확인을 맡습니다. 코드 수정과 머지는 일꾼이 담당합니다.

Claude Code · Codex · Antigravity가 한 트래커를 함께 씁니다. 각자 저장소 루트에서 평소처럼 대화형으로 엽니다.

감독가능(/moai-supervise)일꾼만일꾼만
  • 감독은 Claude Code만 맡습니다. Codex는 tmux 칸이나 cmux 탭의 일꾼으로 일을 받습니다. Codex 일꾼은 테스트와 커밋을 마친 뒤 대기합니다. 감독 쪽 리뷰가 끝나면 머지 지시를 받습니다.
  • moai skill install --agent auto는 PATH에 있는 claude · codex · agy를 찾아 한 번에 설치합니다.
  • Codex와 Antigravity는 같은 .agents/skills/를 읽으니, 커밋해 두면 팀 전체가 같은 스킬을 씁니다.
  • 일을 마친 에이전트는 이슈에 model: <회사>/<모델> 한 줄을 남깁니다. moai stats가 이 기록을 모아 모델별 작업량을 보여 줍니다.
