moai の使い方

インストール

インストールスクリプトはリリースファイルと SHA256SUMS を一緒にダウンロードし、チェックサムが合わなければインストールしません。この検査を無効にするオプションはありません。

macOS · Linux

curl -fsSL https://raw.githubusercontent.com/buzzni/moai/main/install.sh | sh
  • インストール先は ~/.local/bin です。このディレクトリが PATH に含まれていれば moai で呼び出せます。
  • 別の場所や特定のバージョンでインストールするには、-s -- の後にオプションを付けます。 
    curl -fsSL https://raw.githubusercontent.com/buzzni/moai/main/install.sh \
  | sh -s -- --dir ~/bin --version v0.1.0

Windows

PowerShell でスクリプトをダウンロードし、ファイルとして実行します。

Invoke-WebRequest -UseBasicParsing -OutFile install.ps1 https://raw.githubusercontent.com/buzzni/moai/main/install.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File install.ps1
  • インストール先は %LOCALAPPDATA%\Programs\moai です。-Dir で場所を、-Version でバージョンを選べます。
  • インストールスクリプトは PATH を変更しません。インストール先が PATH にない場合は一行で知らせます。
  • irm … | iex のようにパイプで実行する方法には対応していません。スクリプトの終了とともに PowerShell のウィンドウも閉じてしまうためです。
  • Visual C++ 再頒布可能パッケージのないクリーンな PC でもそのまま動きます。

アップデート

moai update

実行中の moai を最新リリースに置き換えます。新しいバージョンが出ると moai tui の画面上部にも表示されます。最初にインストールしたときのコマンドをもう一度実行してもアップデートできます。

対応プラットフォーム

ビルド済みバイナリは Linux（x86_64）、macOS（Apple Silicon）、Windows（x86_64・ARM64）向けがあります。それ以外の環境ではソースから cargo build --release でビルドします。

はじめに

moai で管理するプロジェクトのルートで一度実行します。

cd <プロジェクト>
moai init

ターミナルで実行すると、まず設定画面が表示されます。各項目にはデフォルト値が選ばれています。Enter を押すと選んだ設定で初期化し、Esc を押すと何も変更せずに終了します。

moai init
項目何を決めるか選び方
id プレフィックスイシュー id の先頭部分です（moai-ae8y の moai）。デフォルトはディレクトリ名です後から変更できないので、短く分かりやすい名前にします
トラッカーを git に載せるかcommit：リポジトリにコミットしてチームと共有します（デフォルト）
exclude：自分のクローンだけに置き、.git/info/exclude で隠します
gitignore：自分のクローンだけに置き、.gitignore で隠します		チームで使うなら commit、他人のリポジトリで自分の作業だけを管理するなら exclude
エージェント向けガイドの置き場所block：AGENTS.md の中にガイド全体を入れます
file：ガイドは .moai/guide.md に置き、AGENTS.md にはリンクだけを残します
hook：AGENTS.md には触れず、フックが Claude に伝えます
none：何も書きません		AGENTS.md を短く保ちたいなら file。トラッカーを git に載せないなら hook
フックとスキルのインストールClaude Code プラグイン（スキルとフック）をインストールしますエージェントと一緒に使うならオンにします。下のフックについてを参照
└ オプションのスキルmoai-tmux · moai-cmux · moai-saycode が一行ずつ表示されます使っている作業環境に合わせてオンにします。いま tmux・cmux・Saycode の中で実行していれば、その行は最初からオンになっています
マージドライバー二つのブランチが別々のイシューを変更したとき、git がイシュー単位で自動的にマージしますトラッカーを git に載せるならオンにします（クローンごとに一度必要です）
プロジェクト一覧に追加このリポジトリを自分のプロジェクト一覧に登録します複数のプロジェクトを扱うならオンにします。プロジェクトの外で moai を実行すると、登録したプロジェクトを一画面にまとめて表示します
  • Claude Code は AGENTS.md ではなく CLAUDE.md を読みます。CLAUDE.md に @AGENTS.md の一行を入れておけば両方が読まれます。
  • Codex・Antigravity でも使うには、moai skill install --agent codex、--agent antigravity でそれぞれのスキルとフックをインストールします。
  • moai をアップデートしたら moai init をもう一度実行し、ガイドを新しいバージョンにします。イシューと履歴には触れません。

インストールが済んだら、エージェントのセッションを開き、いつものように言葉で仕事を頼めば大丈夫です。エージェントはセッションの開始時に moai status で現在のボードを読み、イシューの作成や移動を自分で行います。

tui と web

moai の画面は二つあります。エージェントは画面を開かなくてもトラッカーのファイルを直接読み書きします。ユーザーは進み具合を確認したいときに好きな画面を開けば十分です。

moai tui — ターミナルで

moai tui

一覧、カンバン、ガント、統計、Wiki をターミナルで見ます。SPC g を押してから画面ごとのキーを一つ押すと切り替わります。次に起動すると、最後に見ていた一覧、カンバン、ガントの画面が開きます。

moai tui
  • マウスで行をクリックしたりスクロールしたり、ペインの幅を変えたりできます。すべてのキーの一覧は moai tui --help で確認します。
  • SPC n を押すと、思いついたことをすぐバックログに書き留められます。

moai web — ブラウザで

moai web

127.0.0.1:6624 で一覧、カンバン、ガント、Wiki を見ます。ブラウザは自分で開きます。ターミナルに慣れていないメンバーと進み具合を共有するときに使えます。

  • キーは tui とほぼ同じです。ペインの間を移るときだけ Ctrl-w の代わりに SPC w を使います。統計は tui でだけ見られます。
  • ガントのバーをドラッグして日付を変えられます。それ以外のトラッカーの内容は読むだけです。
  • ポートがすでに使われている場合は --port で別のポートを指定します。--port 0 を渡すと空いているポートを選びます。
  • 止めるときは Ctrl-C を押します。

一覧 — マイルストーンとエピックをフォルダのように

マイルストーンとエピックを展開したり、その中に入ったりしてイシューを探します。カーソルのあるイシューの説明、サブイシュー、コミット、履歴は横に表示されます。tui と web のどちらも SPC g l で開きます。

moai tui
127.0.0.1:6624
  • Enter でマイルストーンやエピックに入り、Backspace で出ます。l は一段展開し、h は折りたたみます。Tab は配下をすべて展開します。
  • / を押して検索語を入力すると、タイトル、タグ、本文、ノートからすぐに探します。隠したイシューも検索されます。アーカイブしたイシューは、web では SPC v o でアーカイブを表示しているときだけ検索されます。
  • SPC f で状態、担当者、タグ、マイルストーンなどの条件をかけられます。入力中は選べる値が上に表示されます。
  • SPC s で優先度、期限、更新時刻など複数の基準を組み合わせて並べ替えます。並べ替えの設定は次に起動したときも残ります。
  • 自分に割り当てられたイシューに変更があると [NEW] が付きます。r で既読にします。

カンバン — 状態別のボード

イシューを状態ごとに分けてカードで表示します。マイルストーンごとに一行ずつ並ぶので、リリースごとの進み具合が分かります。tui と web のどちらも SPC g b で開きます。

moai tui
127.0.0.1:6624
  • バックログと先送りした作業も別の列に表示されます。先送りの列は最初は隠れていて、SPC v l で表示します。
  • tui では他の人のカードに担当者が表示されます。web では SPC c a で担当者を表示します。
  • h、l で列を移り、j、k で列の中のカードを行き来します。
  • 一覧とカーソル位置、フィルター、表示設定を共有します。二つの画面を行き来しても見ていた位置はそのままです。
  • カードを手で動かすことはできません。状態はエージェントが作業しながら変えます。

ガント — 予定をバーで

一覧の横に日付の軸を付け、イシューごとに計画した期間と実際に作業した期間をバーで表示します。tui と web のどちらも SPC g g で開きます。

moai tui
127.0.0.1:6624
  • 薄いバーは計画した開始日から期限まで、色付きのバーは実際に作業した期間です。期限を過ぎた部分は赤い斜線で表示されます。
  • エピックとマイルストーンは、メンバーの期間をまとめて斜線のバーで表示します。
  • 時間・日・週・月の単位で広げたり縮めたりできます。t で今日に戻り、z ですべてのバーを一画面に収めます。
  • カーソルのあるイシューをブロックしているイシューは矢印でつながります。
  • バーをマウスでドラッグすると開始日と期限が変わります。手を離したときに一度だけ保存され、上のエピックやマイルストーンの期限を超える場合は保存せずに理由を知らせます。

統計 — 流れとかかった時間

プロジェクトの作業状況を棒グラフと数値で見ます。tui では SPC g s で開きます。web にはありません。

moai tui
  • 週ごとに作った作業と終えた作業を並べて表示します。b で週単位と日単位を切り替えます。
  • 状態別、優先度別のイシュー数を確認できます。
  • 作成から完了まで、作業開始から完了までにかかった時間の中央値と p90 を表示します。開始時刻が分からない作業は 0 として数えず、別に数えます。
  • イシューに記録されたモデル名をもとに、AI モデルごとの作業数を集計します。
  • フィルターが設定されていれば、条件に合うイシューだけを集計します。

Wiki — リポジトリのマニュアル

リポジトリのマークダウン文書を画面の中で読みます。tui と web のどちらも SPC g w で開きます。

moai tui
127.0.0.1:6624
  • 片側にページの一覧、もう片側に選んだページの内容が表示されます。
  • / でタイトルと本文を検索します。検索語によく合うページから表示されます。
  • ページ内のリンクは Tab で選んで Enter で開きます。Backspace を押すと前に読んでいた行に戻ります。
  • イシューの詳細では、コミットの下にそのイシューを扱う Wiki ページと関連する節も表示されます。
  • Wiki は読み取り専用です。ページはリポジトリのファイルとして管理し、エージェントが作業を終えるときに編集してコミットします。

moai で始める開発の指示

大きな作業はマイルストーンとエピックに分けます

moai ではエピックとマイルストーンでイシューをまとめて管理します。

  • エピック — 一つの目的のためのイシューのまとまりです。複数のファイルを変更する依頼なら、エージェントがエピック一つとイシュー 3〜7 個に分けた計画をまず見せ、承認すると一度に作成します。
  • マイルストーン — 一度にリリースする単位です。エピックをマイルストーンにつなぐと、その下のイシューも一緒に含まれます。

エピックとマイルストーンの状態は手で動かしません。配下の作業を一つでも始めれば進行中に、すべて終われば完了に自動で変わります。

マイルストーンが進行中のあいだは、その中の作業が優先です。moai ready は進行中のマイルストーンの作業と p0（緊急）だけを渡し、残りは後回しにします。進行中のマイルストーンに作業を追加するかどうかはユーザーが決めます。

計画を見せるとき、エージェントは期限も一緒に尋ねます。答えがなければ期限なしのままにします。

ワークツリーを作ってマージするまで

複数のセッションが一つのブランチにコミットを積むと、マージのときにお互いを待つことになります。moai のエージェントは作業ごとに別のブランチを作ります。

  1. 作業を引き受けます。イシューを in_progress に移します（moai mv <id> in_progress --from todo）。ほかのセッションがすでに引き受けていれば移さず、次の作業に進みます。
  2. ワークツリーを作ります。リポジトリ内の .worktrees/<エピック> に新しいブランチでチェックアウトします。Claude Code・Codex・Antigravity がすべて同じ場所を使います。
  3. その中で作業してコミットします。コミットの件名にイシュー id を書いておくと、moai show <id> がそのイシューのコミットを見つけて表示します。
  4. レビューを受けます。エピックが終わったらエピック全体を一度レビューし、指摘を反映します。
  5. マージして片付けます。ベースブランチに --no-ff でマージし、ワークツリーとブランチを削除してからイシューを done に移します。
  • トラッカーは常にルートにあります。ワークツリーの中で moai を実行しても、ルートの .moai/ を読み書きします。ほかのセッションからも誰が何を引き受けたかがすぐ分かり、マージのときにトラッカーのファイルが衝突しません。
  • マイルストーンに属する作業はマイルストーンのブランチから始めます。milestone/<マイルストーン id> ブランチからエピックのブランチを作り、作業が終わったらマイルストーンのブランチにマージし直します。マイルストーンのブランチはリリースのときに一度にベースブランチへ入ります。
  • 隣のワークツリーが何をしているかは moai ready --worktree で確認します。

バックログ

いますぐやらないことはバックログに入れます。

moai backlog add 'ボードをエピックごとに折りたためたらどうか'
moai backlog ls
moai backlog
  • バックログは、まだ実行する作業として確定していないアイデアです。ボードと moai ready には表示されません。
  • 作業中に思いついたアイデアがいまの範囲を外れるなら、バックログに残しておきます。
  • 時が来たら moai backlog promote <id> でエピックとイシューを作ります。元のバックログは閉じられ、新しい作業の履歴から元のメモをたどれます。
  • すでに作った作業をいまはやらないと決めたなら、バックログではなく moai defer <id> -m '理由' で先送りします。--undo でそのまま元に戻せます。

使用例

エージェントには言葉で指示します。たとえば次のように頼めます。

バックログの整理

たまったバックログを整理して。重なっているものはまとめて、もう終わったものは閉じて、いまやる価値があるものには優先度を付けて。

たまったバックログを空いているセッションに配って。

二つ目の頼み方は監督（/moai-supervise）を呼び出します。下の監督とワーカーを参照。

計画は Fable で、詳しく

この作業の計画は Claude Fable で立てて、ほかのエージェントがすぐ参照できるように説明を詳しく書いて。

計画の段階で、イシューの本文に何をなぜするのか、どこまで進めるのか、どのファイルを変更するのかをまとめておけば、ほかのエージェントも文脈をつかんで作業を引き継げます。

開発とレビューに別のモデルを使う

各ワーカーセッションでサブエージェントを使って、Sonnet 5.5 medium で開発し、Opus 5.5 high でレビューして。

毎回言わずに済ませるには、役割ごとのモデルをユーザー設定に書いておきます。監督は作業を配るたびにこの値を読みます。moai models でいまの値を確認できます。

[models]
plan    = "fable"    # 計画
develop = "sonnet"   # 開発 — ほとんどの作業
complex = "opus"     # 書き込み経路・並行性・複数ファイルにまたがる作業
review  = "opus"     # エピック終了時のレビュー
review_grade = "high"
effort       = "medium"

対応する作業環境

監督がワーカーのウィンドウを確認・操作できる環境では、セッションの管理まで任せられます。使っている環境に合ったオプションのスキルをオンにします（moai init のオプションのスキルの行、または moai skill install --with <スキル>）。

  • tmux — moai-tmux。監督がワーカーのペインにラベルを付け、報告が終わったペインを /clear で空にし、届かなかったメッセージを貼り付けます。ワーカーが足りなければ、許可を得てから新しいペインを開きます。
  • cmux — moai-cmux（cmux 0.65.0 以上）。tmux と同じことを cmux のタブで行います。
  • Saycode — moai-saycode。Saycode のセッションの中で、監督が happy agent でワーカーのセッションを確認し、作業を送り、新しいセッションを開きます。

どの環境でも、監督はユーザーのペイン・タブ・セッションを閉じず、入力欄に人が書きかけた文字があれば触れません。

フックについて

moai skill install（または moai init のフック・スキルのインストール）を行うと、エージェントのセッションの要所で moai のフックが実行されます。

いつ何をするか
セッション開始警告の基準点を記録します。コンテキストが圧縮された後は、進めていた作業をもう一度伝えます
最初のプロンプトmoai status のボードを一度読み込ませます
ツール実行の前下の五つのルールを確認します
ターン終了進行中の作業が残っていれば、次のセッションのために Next: メモを残すよう促します

フックが守る五つのルール：

  1. 新しいイシューはいま引き受けている作業の範囲内で作ります。範囲外ならバックログに送ります。
  2. リポジトリを変更する前に作業を引き受けます。
  3. レビューもイシューとして残します。何を見るのか、何を反映したのかを書きます。
  4. ユーザーの tmux サーバーを止めません。
  5. ほかのエージェントの作業を引き受けるときは先に確認します。

拒否するときは通るコマンドをそのまま示すので、エージェントは人を待たずにすぐ直します（人に尋ねるのは 5 番だけです）。フックがセッションを失敗させることはなく、ターミナルで人が直接打つ moai はフックを通りません。

監督とワーカー

Claude Code のセッションの一つで /moai-supervise を呼び出すと、そのセッションが監督になります。監督はリポジトリごとに一つだけ置きます。

tmux · moai tui · Claude Code · Codex · Antigravity
  1. 監督が互いに重ならないバックログを選びます。期限がなければ尋ねます。
  2. 作業の難しさに合った役割（開発・複雑な作業・ドキュメント・雑務）を選び、その役割のモデルでワーカーを立ち上げます。デフォルトは監督セッション内のサブエージェントです。
  3. ワーカーはバックログをエピックに具体化し、ワークツリーで作業し、レビュー・マージ・片付けまで済ませてから報告します。
  4. 監督はマージされたか、エピックが閉じたか、ワークツリーが削除されたかを確認し、次の作業を送ります。
  • ワーカーのウィンドウを自分で見たいなら、サブエージェントの代わりにセッションワーカーを使います。リポジトリのルートで Claude Code のセッションをいくつか開いておけば、監督が空いているセッションに作業を送ります。
  • 設計上の判断が必要になるとワーカーが止まり、監督が人に尋ねます。席を外すときに監督へ伝えておけば、ワーカーが推奨案で決めて理由をイシューに残します。
  • 監督は作業の選定と割り当て、結果の確認を担当します。コードの変更とマージはワーカーが担当します。

複数ベンダーのエージェントを一緒に使う

Claude Code・Codex・Antigravity が一つのトラッカーを共有します。それぞれリポジトリのルートで、いつも通り対話型で開きます。

監督可能（/moai-supervise）ワーカーのみワーカーのみ
  • 監督を務めるのは Claude Code だけです。Codex は tmux のペインや cmux のタブのワーカーとして作業を受け取ります。Codex のワーカーはテストとコミットを終えると待機し、監督側のレビューが終わるとマージの指示を受けます。
  • moai skill install --agent auto は PATH にある claude · codex · agy を見つけて一度にインストールします。
  • Codex と Antigravity は同じ .agents/skills/ を読むので、コミットしておけばチーム全員が同じスキルを使えます。
  • 作業を終えたエージェントはイシューに model: <会社>/<モデル> の一行を残します。moai stats がこの記録を集めて、モデルごとの作業量を表示します。
