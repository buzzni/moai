# Wait on a process by its PID or output, never by a pattern it matches itself

## What happened

- In `moai-w792`, a worker polled for the completion of its own `cargo test` using `until … && ! pgrep -f "cargo test --workspace"; do sleep 5; done`.
- The waiting process's own `bash -c` command line contained that exact text, so `pgrep -f` continuously matched itself, causing the loop to run indefinitely. This occurred twice in the same epic across two different patterns.

## Why

- `pgrep -f` evaluates the full command-line arguments of every process, including the shell executing the polling loop.
- An infinite loop is indistinguishable from a command that is still waiting, providing no indication that it is stuck.

## Do this instead

- Poll the output generated by the command or monitor the spawned PID (`kill -0 <pid>`), rather than performing a pattern search across the process table.
- If a process name search is necessary, bracket a character in the pattern so it cannot match its own command line: `pgrep -f "[c]argo test --workspace"`.

Learned in: moai-w792
